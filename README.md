# 🇪🇸 혼자보는 스페인어 / 같이보는 스페인어 — 텔레그램 봇

1시간마다 생활 스페인어 **문장**과 공항·숙소·식당·쇼핑 등에서 바로 쓰는 **단어**를
번갈아 텔레그램으로 보내주는 봇입니다.
**말하기 연습이 목적**이라 스페인어 철자 대신 **한글 발음**을 크게 보여줍니다.

Cloudflare Workers에서 서버리스로 동작하므로 **PC를 켜둘 필요가 없습니다.**

## "혼자보는" / "같이보는" 은 뭐가 다른가요?

**코드는 완전히 같습니다.** 봇 하나를 텔레그램의 어디에 연결하느냐만 다릅니다.

- **혼자보는 스페인어** — 봇과 나의 1:1 대화창에서 받아보기. 나만의 진도.
- **같이보는 스페인어** — 봇을 텔레그램 그룹이나 채널에 초대해서 친구들과
  같이 받아보기. 그 방에 있는 모두가 같은 문장을 같은 시간에 봅니다.

봇을 **개인 대화 + 그룹**에 동시에 추가하면 진도(무슨 문장까지 봤는지)가
공유됩니다. 개인 진도와 그룹 진도를 **완전히 따로** 두고 싶다면, 이 저장소를
그대로 한 번 더 배포해서(② 배포 방법 참고) 봇을 두 개 만들면 됩니다.
그 경우 하나는 나만 채팅하는 "혼자보는" 봇으로, 다른 하나는 그룹에 초대하는
"같이보는" 봇으로 씁니다.

## 메시지 예시

문장 차례:

```
🇪🇸 오늘의 한 문장

🗣 꾸안또 꾸에스따 에스또

💬 이거 얼마예요?
📍 가격을 물어볼 때

🧩 끊어서 보기
· 꾸안또 꾸에스따(¿Cuánto cuesta) — 얼마나 비용이 드나요
· 에스또(esto?) — 이것은

💡 물건을 손으로 가리키면서 물으면 확실합니다.

📈 1/36문장 (3%) · 1회차
```

단어 차례 (생활·여행 어휘):

```
📖 오늘의 단어

equipaje

🗣 짐, 수하물 / 에끼빠헤

💬 여행 가방 등 부치는 짐 전체를 가리키는 말.
📍 체크인·수하물 찾는 곳

📈 1/40단어 (3%) · 1회차
```

단어 중에는 영어 단어와 철자·발음이 비슷해 뜻을 오해하기 쉬운 **가짜 친구
(falsos amigos)** 단어도 섞여 있어, 이 경우엔 포맷이 조금 달라집니다:

```
🤔 착각하기 쉬운 단어

embarazada

🗣 임신한 / 엠바라사다

❌ 착각하기 쉬운 뜻 — 영어 embarrassed(당황한)와 철자가 비슷해 착각하기 쉬움
✅ 실제 뜻 — 임신한 (pregnant)

📈 5/40단어 (13%) · 1회차
```

바로 뒤에 **발음 음성(mp3)** 이 이어서 전송됩니다.

## 특징

- **문장 ↔ 단어 번갈아 출제** — 정기 발송·`/now`·`/start` 모두 이전과
  다른 종류를 보냄 (문장 다음엔 단어, 단어 다음엔 문장)
- **한글 발음 병기** — 스페인어 철자를 몰라도 바로 따라 읽을 수 있음
- **낱말 끊어 보기** — 문장을 조각내 뜻을 하나씩 보여줘서 응용이 가능함
  (예: `꾸안또 꾸에스따 에스또` → `꾸안또 꾸에스따`(얼마나 비용이 드나요) +
  `에스또`(이것은)) 조각마다 스페인어 원문을 괄호로 같이 보여줍니다. 단
  **한글 발음이 1순위**이고 스페인어는 보조라, 철자를 몰라도 그대로 따라
  읽으면 됩니다.
- **생활·여행 단어 40개** — 공항·숙소·식당·쇼핑·응급상황 등 실전 어휘.
  그중 10개는 영어 단어와 헷갈리기 쉬운 '가짜 친구' 단어(embarazada,
  actualmente, éxito 등)라 착각하기 쉬운 뜻과 실제 뜻을 나란히 대조해서 보여줌
- **발음 음성 첨부** — 뉴럴 원어민 발음, 말하기 속도 조정 가능 (API 키 불필요).
  일반 파일(`sendDocument`)로 보내므로 텔레그램의 음성/오디오 자동
  이어재생 재생목록에 묶이지 않고, 누른 것만 재생됨
- **중복 없는 순환 출제** — 문장 36개, 단어 40개를 각각 다 볼 때까지 같은 게 안 나옴
- **진도 영구 저장** — D1 데이터베이스에 기록되어 언제든 이어서 학습
- **조용한 시간** — 자는 동안(기본 0~7시)은 알림을 보내지 않음
- **24시간 자동 실행** — Cloudflare Cron 트리거가 매시 정각에 워커를 깨움
- **중복 발송 방지** — 같은 시간대에 여러 번 호출돼도 딱 한 번만 발송
- **밀린 문장 따라잡기** — 스케줄러가 멈춰도 봇에 말을 걸면 그 시점에 발송
- **개인·그룹 모두 지원** — 봇을 그룹/채널에 초대하면 자동으로 등록되어
  다 같이 받아볼 수 있음 (👉 "혼자보는/같이보는" 설명 참고)

## 명령어

| 명령어 | 설명 |
|--------|------|
| `/start` | 봇 시작 & 채팅 등록 |
| `/now` | 지금 바로 한 문장 받기 |
| `/again` | 진도와 상관없이 문장/단어 중 아무거나 하나 |
| `/stats` | 학습 진도 보기 |
| `/reset` | 진도 처음부터 다시 |
| `/stop` | 정기 발송 중지 |
| `/help` | 도움말 |

## 아키텍처

```
텔레그램 ──웹훅──▶ POST /webhook  → 명령어 즉시 응답
Cron 트리거 ─────▶ scheduled()   → 정기 발송
(매시 정각)               │
                          ▼
                D1 (구독자 · 진도 · 발송슬롯)
```

일반 서버처럼 상시 실행되지 않고, **요청이 있을 때만 깨어나는** 방식이라
무료 한도 안에서 넉넉하게 동작합니다.

### 정기 발송은 Cloudflare Cron 트리거

`wrangler.jsonc` 의 `triggers.crons` 에 매시 정각(`0 * * * *`)이 걸려 있고,
Cloudflare 가 그 시각에 워커의 `scheduled` 핸들러를 직접 깨웁니다.
외부 스케줄러가 필요 없습니다.

`GET /cron` 경로는 그대로 남아 있어, 수동으로 한 번 발송을 밀어 넣거나
외부 스케줄러를 추가로 붙이고 싶을 때 쓸 수 있습니다.

중복 발송은 워커가 막습니다. `/cron` 은 먼저 현재 시간 슬롯
(`YYYY-MM-DD-HH`, KST 기준)을 `sent_slots` 테이블에 선점(`PRIMARY KEY`)하고,
이미 선점된 슬롯이면 발송을 건너뜁니다. 따라서 스케줄러가 재시도하거나 여러 곳에서
동시에 호출해도 **한 시간에 한 문장**이 보장됩니다.

```
1번째 호출 → {"ok":true,"slot":"2026-08-03-19","sent":1,"failed":0}
2번째 호출 → {"ok":true,"skipped":"already_sent","slot":"2026-08-03-19"}
조용한 시간 → {"ok":true,"skipped":"quiet_hours","hour":3}
```

#### `/cron` 은 왜 키가 없나

`/cron` 은 다른 관리 엔드포인트와 달리 `ADMIN_KEY` 를 요구하지 않습니다.
스케줄러 쪽에 비밀값을 등록하는 수동 설정 단계를 없애기 위한 선택이며,
다음 두 가지 때문에 안전합니다.

1. 시간 슬롯 선점 때문에 **한 시간에 최대 한 문장**만 나갑니다.
   외부에서 아무리 많이 호출해도 메시지 도배나 문장 조기 소모가 없습니다.
2. 응답에는 슬롯 정보와 발송 건수만 담기며, 학습 데이터나 토큰이 노출되지 않습니다.

`/status`, `/send` 등 상태를 읽거나 강제 발송하는 엔드포인트는 그대로
`ADMIN_KEY` 로 보호됩니다.

### 스케줄러가 멈춰도 되는 안전망

Cron 이 밀리거나 거를 수 있습니다.
그래서 **봇에게 아무 메시지나 보내면** 이번 시간 몫이 아직 안 나갔는지 확인하고
밀려 있으면 바로 발송합니다.

- `/stats`, `/help` 처럼 문장을 주지 않는 명령 → 밀린 문장이 있으면 따라서 발송
- `/start`, `/now` → 이미 문장을 받았으므로 이번 시간 몫을 채운 것으로 처리
  (직후에 정기 발송이 겹쳐 오지 않음)
- 조용한 시간에는 따라잡기도 하지 않음

여기서도 슬롯 선점이 적용되므로 한 시간에 한 문장 규칙은 그대로 지켜집니다.

## 프로젝트 구조

```
├── src/
│   ├── index.js      # 웹훅 수신 + /cron 발송 + 관리 엔드포인트
│   ├── store.js      # D1 구독자·진도 관리 + 문장/단어 교대 로직
│   ├── telegram.js   # 텔레그램 Bot API 래퍼
│   ├── format.js     # 메시지 포맷팅
│   ├── tts.js        # 발음 음성 생성
│   ├── phrases.js    # 문장 데이터 (자동 생성)
│   └── words.js      # 단어 데이터 (자동 생성)
├── data/
│   ├── phrases.json  # 문장 원본 36개
│   └── words.json    # 단어 원본 40개
├── migrations/       # D1 스키마 (0001 초기, 0002 발송슬롯, 0003 단어)
├── scripts/          # 문장·단어 변환 스크립트
├── .github/workflows/deploy.yml  # 자동 배포
└── wrangler.jsonc    # Worker 설정
```

## 배포 방법

**GitHub 에 코드가 올라가면 자동으로 배포됩니다.**
`main` 브랜치에 푸시하면 `.github/workflows/deploy.yml` 이
D1 생성 → 스키마 적용 → 배포 → 시크릿 등록 → 웹훅 재등록까지 전부 처리합니다.
터미널도, 로컬 설치도 필요 없습니다.

처음 한 번만 아래 준비가 필요합니다. **"혼자보는" 봇과 "같이보는" 봇을 따로
두고 싶다면 이 저장소를 복제(fork 또는 새 저장소로 복사)해서 아래 과정을
두 번 반복**하면 됩니다(1번 봇 토큰만 서로 다르게).

### 1. 봇 토큰 받기
텔레그램 [@BotFather](https://t.me/BotFather) 에서 `/newbot` 으로 봇을 만들고
토큰을 받습니다. 이미 봇이 있으면 `/mybots` → 해당 봇 → *API Token* 에서 확인합니다.

### 2. Cloudflare API 토큰 만들기
[dash.cloudflare.com/profile/api-tokens](https://dash.cloudflare.com/profile/api-tokens)
→ **Create Token** → **Edit Cloudflare Workers** 템플릿 사용.
생성된 토큰 문자열을 복사해 둡니다(다시 볼 수 없습니다).
D1 권한이 템플릿에 포함되지 않으므로 토큰 편집 화면에서
**Account → D1 → Edit** 권한을 추가로 넣어야 합니다.

### 3. GitHub Secrets 등록
저장소 **Settings → Secrets and variables → Actions → New repository secret**
에서 아래 4개를 등록합니다.

| 이름 | 값 |
|------|-----|
| `CLOUDFLARE_API_TOKEN` | 2번에서 만든 토큰 |
| `TELEGRAM_BOT_TOKEN` | 1번에서 받은 봇 토큰 |
| `WEBHOOK_SECRET` | 아무 임의 문자열 (웹훅 위조 방지용) |
| `ADMIN_KEY` | 아무 임의 문자열 (관리 엔드포인트 접근용) |

### 4. 배포 실행
**Actions** 탭 → *Cloudflare 배포* → **Run workflow** 를 누릅니다.
(이후로는 `main` 에 푸시할 때마다 자동 실행됩니다.)

성공하면 실행 요약에 워커 주소(`https://....workers.dev`)가 표시됩니다.
웹훅 등록까지 워크플로가 끝내므로 따로 `/setup` 을 열 필요가 없습니다.

### 5. 봇에게 /start (또는 그룹에 초대)
- **혼자보는**: 텔레그램에서 봇을 찾아 `/start` 를 보내면 등록 완료입니다.
- **같이보는**: 봇을 그룹/채널에 **관리자로** 초대하면 자동으로 등록됩니다
  (초대 직후 안내 메시지가 옵니다).

이후 매시 정각에 Cloudflare Cron 트리거가 문장을 보냅니다.

## 관리 엔드포인트

아래 세 경로는 `?key=<ADMIN_KEY>` 가 필요합니다.

| 경로 | 설명 |
|------|------|
| `/setup` | 웹훅 등록 + 명령어 목록 등록 |
| `/status` | 봇·웹훅·구독자·진도 상태 조회 |
| `/send` | 즉시 발송 (조용한 시간·중복 방지 무시, 테스트용) |

`/send` 는 속도·성우를 그자리에서 바꿔 들어보는 매개변수를 받습니다.

```
/send?key=...&rate=+20%                 # 20% 빠르게
/send?key=...&voice=es-ES-AlvaroNeural  # 스페인 본토 남성 성우
```

발송 대상을 직접 관리하고 싶을 때는 `/subs`, `/unsubscribe` 를 씁니다
(그룹으로 옮긴 뒤 개인 알림만 끄고 싶을 때 등에 유용합니다).

```
/subs?key=...&add=@내채널이름           # 채널·그룹을 대상에 추가
/subs?key=...&remove=<chat_id>          # 특정 대상 제거
/unsubscribe?key=...&chat_id=123456     # 개인 알림 끄기
```

`/cron` 은 스케줄러가 호출하는 경로로, 위와 달리 **키가 필요하지 않습니다.**
(이유는 [`/cron` 은 왜 키가 없나](#cron-은-왜-키가-없나) 참고)

## 설정 변경 (wrangler.jsonc 의 vars)

| 항목 | 기본값 | 설명 |
|------|--------|------|
| `INTERVAL_HOURS` | `1` | 안내 문구에 표시할 주기 |
| `TIMEZONE` | `Asia/Seoul` | 조용한 시간 판정 기준 |
| `QUIET_ENABLED` | `true` | 조용한 시간 사용 여부 |
| `QUIET_START_HOUR` | `0` | 조용한 시간 시작 |
| `QUIET_END_HOUR` | `7` | 조용한 시간 끝 |
| `SEND_VOICE` | `true` | 발음 음성 함께 보내기 |
| `SHOW_SPANISH` | `false` | 스페인어 원문 표시 |
| `VOICE_RATE` | `+0%` | 말하기 속도. `+0%` 가 원어민 보통 속도 |
| `VOICE_NAME` | `es-MX-DaliaNeural` | 성우 (중남미 발음. 스페인 본토는 `es-ES-ElviraNeural`) |

> 실제 발송 주기는 `wrangler.jsonc` 의 **`triggers.crons`** 로 정해집니다.
> 예) 2시간마다 → `"0 */2 * * *"` 로 바꾼 뒤 배포.
> `INTERVAL_HOURS` 는 안내 문구 표시용일 뿐 실제 주기를 바꾸지 않습니다.

### 스페인 본토 발음으로 바꾸려면

기본은 중남미(멕시코) 발음(`es-MX-DaliaNeural`)입니다. 이 저장소의 한글
발음 표기는 `c`/`z` 를 항상 'ㅅ' 소리로 적는 **세세오(seseo)** 방식이라
중남미 발음과 맞습니다. 스페인 본토 발음(`es-ES-...`)은 `c`(e, i 앞)와
`z` 를 영어 th 처럼 발음해 한글 표기와 살짝 다르게 들릴 수 있다는 점을
참고하세요.

## 문장 추가하기

`data/phrases.json` 에 아래 형식으로 추가한 뒤 변환 스크립트를 실행합니다.

```json
{
  "es": "Gracias, de nada",
  "kr_read": "그라시아스, 데 나다",
  "ko": "감사합니다, 천만에요",
  "scene": "감사 인사를 주고받을 때",
  "tip": "정말 고마울 땐 muchas gracias 라고 강조합니다.",
  "parts": [
    { "kr": "그라시아스", "es": "Gracias", "ko": "감사합니다" },
    { "kr": "데 나다", "es": "de nada", "ko": "천만에요" }
  ],
  "level": 1
}
```

```bash
npm run build:phrases   # data/phrases.json → src/phrases.js
```

- 문장의 `es` 는 화면에 안 나와도 **음성 생성에 쓰이므로 반드시** 채워야 합니다.
- `parts` 는 낱말 조각입니다. `kr`(한글 발음)이 필수이고, `es`(스페인어 원문)는
  괄호 안 보조 표기라 없으면 괄호 없이 출력됩니다.

`npm run build:phrases` 는 조각이 원문을 그대로 복원하는지 검증한 뒤에만
`src/phrases.js` 를 만듭니다. 어긋나면 빌드가 실패하므로 잘못 쪼갠 데이터가
배포까지 흘러가지 않습니다.

```
조각 kr 이어붙이기 == kr_read   (공백·쉼표 무시)
조각 es 이어붙이기 == es        (구두점 무시, es 를 모두 채운 경우만)
```

## 단어 추가하기

`data/words.json` 에 추가한 뒤 변환 스크립트를 실행합니다. 두 형식이 있습니다.

**일반형** — 공항·숙소·식당 등 생활·여행 어휘 (대부분 이 형식):

```json
{
  "es": "equipaje",
  "kr_read": "에끼빠헤",
  "ko_reading": "짐, 수하물",
  "meaning": "여행 가방 등 부치는 짐 전체를 가리키는 말.",
  "scene": "체크인·수하물 찾는 곳"
}
```

**가짜 친구형** — 영어 단어와 철자·발음이 비슷해 뜻을 오해하기 쉬운 단어
(`real_meaning` 이 있으면 이 형식으로 인식합니다):

```json
{
  "es": "embarazada",
  "kr_read": "엠바라사다",
  "ko_reading": "임신한",
  "guess_meaning": "영어 embarrassed(당황한)와 철자가 비슷해 착각하기 쉬움",
  "real_meaning": "임신한 (pregnant)"
}
```

```bash
npm run build:words   # data/words.json → src/words.js
```

- `es` 는 화면에도 나오고 **음성 생성에도 쓰이므로** 정확한 철자로 채워야 합니다.
- `scene` 은 일반형에서만 쓰는 선택 항목입니다.

## 로컬 개발

```bash
npm install
npm run db:local        # 로컬 D1 초기화 (migrations 전체 적용)
npm run dev             # 개발 서버

# 발송 테스트 (두 번 호출하면 두 번째는 already_sent)
```

`.dev.vars` 파일에 시크릿 3개를 넣으면 로컬에서도 실제 봇으로 테스트할 수 있습니다.

## 발음 음성은 어떻게 만드나

제공자를 순서대로 시도하고, 둘 다 실패하면 음성 없이 텍스트만 보내서
학습이 아예 멈추지 않도록 합니다.

| 생성 수단 | 속도 조정 | 비고 |
|-----------|-----------|------|
| **Edge TTS** (1순위) | 가능 | 뉴럴 음성, `rate` 파라미터가 실제로 반영됨 |
| Google 번역 TTS (대비책) | 불가 | 느리게만 가능, 구두점 제거 시 체감 속도 개선 |

Edge TTS 는 WebSocket + 서명 토큰(`Sec-MS-GEC`, SHA-256)을 쓰는데
Workers 가 둘 다 지원하므로 프로토콜을 `src/tts.js` 에 직접 구현했습니다.
(자세한 구현 배경은 일본어 버전 봇의 README 를 참고하세요 — 프로토콜 자체는
언어에 상관없이 동일합니다.)

### 속도 골라보기

어떤 속도가 편한지 들어보고 `VOICE_RATE` 에 고정하면 됩니다.

```bash
curl "https://<워커주소>/send?key=<ADMIN_KEY>&rate=+0%"
curl "https://<워커주소>/send?key=<ADMIN_KEY>&rate=+20%"
curl "https://<워커주소>/send?key=<ADMIN_KEY>&rate=+35%"
```

## 보안

- 토큰·시크릿은 Cloudflare Secret으로만 관리하며 저장소에 포함되지 않습니다.
- 웹훅은 `secret_token` 헤더를 검사해 위조 요청을 차단합니다.
- `/setup`·`/status`·`/send`·`/subs`·`/unsubscribe` 는 `ADMIN_KEY` 없이는 접근할 수 없습니다.
- `/cron` 은 공개지만 시간당 1회 제한과 정보 미노출로 악용 여지가 없습니다.
- `.env`, `.dev.vars`, `.secrets/` 는 `.gitignore` 처리되어 있습니다.
